Irfaran

A self-hosted fog-of-war map of everywhere you've been.

Self-hosted Your data stays on your hardware AGPL-3.0 Docker Compose

Feed it GPS tracks — live from Overland, OwnTracks or Home Assistant, imported from workout files, or drawn by hand for the years before GPS existed — and it renders a persistent map where the places you've visited are revealed and everywhere else stays under fog. Inspired by Fog of World, but self-hosted, on your own hardware, with your data staying on it.

The name

Irfaran is Old High German: to travel through a thing, and so to come to know it.

It is ir- (through, to completion) on faran, to go — the same root that gives modern German fahren and English fare, ferry and wayfarer. What it became is erfahren, to experience, and Erfahrung, experience itself: in German, what you know is quite literally what you have travelled through.

Which is the whole idea. A map that stays under fog until you have been there does not record where you went — it records what you have come to know by going.

How it works

The design goal is that the map stays fast no matter how much history accumulates. Everything follows from that.

Every track is rasterised once, at import, onto a web-Mercator z14 grid — 256×256 pixel tiles, about 9.5 m per pixel at the equator. Serving a tile is a file read. Nothing is rendered when you ask for it.

The consequence is that display cost is independent of dataset size. A tile takes the same time to serve whether it was built from fifty points or fifty million.

An append-only event log The only source of truth. Every import and every brush stroke is an event with its own geometry, radius and time layer.
Bitmap blobs Derived, disposable.
A rendered PNG pyramid Derived, disposable. Folded up from the blobs to z0, and stamped from the geometry again below z14 so a hand-drawn stroke is not a smear at street level.

Delete both caches, run a rebuild, get byte-identical output. The whole archive can be reprocessed with different brush radii whenever you change your mind — which matters when you are reconstructing places from forty years ago and your relatives keep correcting each other.

What it does

  • Raster fog-of-war rendering that stays fast at every zoom level
  • A trail layer coloured by how often you went, so regular routes stand out
  • Live tracking via Overland, OwnTracks or Home Assistant — all optional, all off by default
  • GPX and TCX import
  • A map per year, plus a cumulative all-time view
  • Manual tools: draw a route, clear fog without claiming one, enclose an area, or erase fog wrongly cleared by GPS drift
  • Pins with titles, colour-coded labels, tags and nested folders
  • Independent light and dark themes for the interface and the map

Getting it running

You need Docker and Docker Compose. Everything runs in two containers: an API and a web server. Both were developed against amd64.

1. Get the code and configure it

git clone https://github.com/n0ne117/Irfaran.git
cd Irfaran
cp .env.example .env

Open .env. You can leave every value as it is for a first run — Irfaran generates its own API token on first start and shows it to you. The settings worth knowing about:

IRFARAN_TOKEN Shared secret for every change. Leave blank to have one generated.
IRFARAN_DATA_HOST Where the database, tiles and blobs live. Defaults to ./data.
IRFARAN_BASEMAP_HOST Where the basemap archive lives. Defaults to the data directory — see below for why you might separate it.
IRFARAN_WEB_PORT Port for the interface. Defaults to 8080.

2. Build and start

docker compose build
docker compose up -d

Open http://localhost:8080. A setup screen appears with your generated API token. Copy it somewhere safe — every browser you want to edit from needs it, and the setup screen is the only place it is offered.

On SELinux hosts — Fedora, RHEL, CentOS — every bind mount needs a :z label or the container is denied access to its own data directory. The bundled Compose files already set it, so there is nothing to do. It is harmless everywhere else.

Running a second copy? Compose names a stack after the folder it is in, so two checkouts in folders both called Irfaran are the same stack as far as it is concerned — starting one replaces the other's containers. Set COMPOSE_PROJECT_NAME in the second one's .env. Your data is untouched either way; it is the containers that get swapped.

3. Check it came up

curl http://localhost:8080/healthz
docker compose exec api python -m irfaran.cli selfcheck

The basemap

Irfaran draws your tracks; the map underneath them is Protomaps PMTiles built from OpenStreetMap. It is far too large to ship in a container, so Irfaran fetches it on first run: the setup screen offers recent Protomaps daily planet builds, or takes a URL of your own if you would rather use a regional extract.

The full planet is around 137 GB, which is hours of downloading. It resumes if interrupted, and the rest of Irfaran works throughout — only the map underneath your trails is missing until it finishes. The archive is verified before it is installed, so a URL that returns an error page is rejected rather than left sitting there looking like a basemap.

Putting it on a different disk. By default the basemap lives in the data directory. That is right for a single-disk machine and wrong for most NAS boxes: 137 GB does not belong on the fast pool your appdata sits on. Set IRFARAN_BASEMAP_HOST to a path on your bulk storage and Compose mounts it separately.

Everything else in the data directory is irreplaceable and measured in megabytes. The basemap is public map data you can always fetch again — so it is the one part worth putting somewhere cheap and slow, and the one part you do not need to back up. 

# .env
IRFARAN_DATA_HOST=/mnt/user/appdata/irfaran
IRFARAN_BASEMAP_HOST=/mnt/user/maps/irfaran

Already downloaded a .pmtiles archive elsewhere? Drop it into that directory as planet.pmtiles and Irfaran will find it on start — the setup screen recognises a basemap that is already installed and simply offers to continue.

Unraid

There is no Community Applications template. Use the Docker Compose Manager plugin, which runs the same Compose file as everywhere else.

  1. Install Docker Compose Manager from Community Applications.
  2. Docker → Compose → Add New Stack, name it irfaran.
  3. Click the cog on the stack and choose Edit Stack → Compose File. Paste the contents of docker-compose.prod.yml from the repository.
  4. Choose Edit Stack → Edit .env and set your paths:
IRFARAN_IMAGE_TAG=0.10.2
IRFARAN_TOKEN=
IRFARAN_DATA_HOST=/mnt/user/appdata/irfaran
IRFARAN_BASEMAP_HOST=/mnt/user/maps/irfaran
IRFARAN_WEB_PORT=8080
  1. Create both share paths first — appdata/irfaran on your cache pool, and a share on the array for the basemap. Unraid will create them on start otherwise, but on whichever disk the share settings pick.
  2. Compose Up. Then open http://your-server:8080.

Put the basemap share on the array, not the cache. A 137 GB download onto a cache pool will either fill it or spend the night being moved by the mover. Set that share's Use cache to No before you start the download.

Running from published images

docker-compose.prod.yml pulls from GitHub Container Registry rather than building: 

docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d

Always pin IRFARAN_IMAGE_TAG to an explicit version. A host that silently changes version when it pulls is a host nobody can debug.

The API token

Reading the map needs nothing. Changing anything — drawing, pins, imports, the data source switches — needs a shared token.

It is a doorstop, not a security model: it stops a misbehaving tracker or a stray curl from altering your history. It does not protect reads, which are open to anyone who can reach the app — so run it somewhere only you can, behind a VPN or a reverse proxy with authentication.

Live tracking

All optional, all off by default, all toggled independently. There is no app to install and no plugin — each source is a small HTTP endpoint that an existing tracker posts to.

Status

Early development, and honest about it. The architecture is settled and tested — several hundred tests cover the coordinate maths, the composite semantics and the rebuild guarantees — but the interface is still moving, and version numbers below 1.0 mean what they usually mean. 1.0.0 is reserved for when it has been running on real data for a while without surprises.

See the changelog for what works right now.

About the images on this page

A fog-of-war map of somebody's life is a map of where they live, work and run. None of the images here show anyone's real movements.

They are genuine output of Irfaran's renderer over invented data: a seeded random walk on a street grid placed in the middle of the Atlantic, generated by synthetic-data.py and composed by synthetic-images.py, both in this directory. The faint streets showing through the cleared fog are drawn by that second script as a stand-in — the real basemap is third-party map data, and not ours to put in a screenshot either.
